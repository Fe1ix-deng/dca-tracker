# Language Switch Design

## Context

The app currently renders Chinese copy directly across the shell, dashboard, operation, history, settings, release notice, backup, quote, and error flows. Users need an English mode that covers the complete interface while preserving Chinese as the default.

## Goals

- Provide Chinese and English as app-wide display languages.
- Cover navigation, headings, labels, buttons, form copy, empty states, confirmations, errors, release notes, and backup/quote notices.
- Keep all calculation, storage, and record data semantics unchanged.
- Persist the selected language in browser `localStorage` and restore it on reload.
- Make language changes apply immediately without a page reload.

## Non-goals

- Translating user-entered plan names, notes, ticker symbols, or imported data values.
- Changing number, currency, or date calculation behavior beyond translating surrounding labels.
- Adding a third-party internationalization dependency.

## Architecture

Add a small `src/i18n` module containing:

- locale resources for `zh-CN` and `en-US`;
- a `createTranslator(language)` helper that supports keyed strings and simple interpolation;
- locale normalization with Chinese fallback for invalid or missing values;
- a storage key for the selected language.

`App` owns the language state, initializes it from storage, writes changes back to storage, and passes the translator (or language plus translator) through the existing component tree. Components replace hard-coded UI copy with translation keys. Domain utilities retain Chinese fallback strings only where they are called outside React; user-facing callers translate those states before rendering.

## User experience

Add a compact language control next to the existing theme and accent controls in both desktop and mobile shell layouts. It uses a two-option segmented control labeled `中` and `EN`, exposes an accessible label, and indicates the active option. Chinese remains selected for first-time users. The control is available regardless of whether a plan exists.

Dynamic values remain generated by current logic and are inserted into translated templates, for example `第 3 期` / `Period 3`, `已完成 2 / 6 期` / `2 / 6 periods completed`, and quote error messages with the existing ticker context.

## Data flow and fallback

1. `useLanguage` (or equivalent app-level state) reads the persisted locale and normalizes it to `zh-CN` or `en-US`.
2. `App` creates a stable translator for the active locale and passes it to `Layout` and the active page.
3. Shell components translate navigation, plan selector, theme/accent labels, release notice, and backup reminder.
4. Page components translate their own copy, including confirmation dialogs and empty/error states.
5. Missing English keys fall back to the Chinese resource so a newly added message never renders blank.

## Testing

Add focused tests for:

- locale normalization and localStorage persistence;
- language control rendering and switching from Chinese to English;
- English copy in each main page and shell notices;
- dynamic interpolation and Chinese fallback for missing keys;
- confirmation/error paths using the active locale.

Run the full Vitest suite and production build after implementation.

# DCA Tracker 第四阶段产品体验修复设计

## 目标

让首次使用者可以直接创建第一份计划，并让计划设置、行情状态、日期状态和金融说明更容易理解、操作和被辅助技术读取。

## 范围与约束

- 保留现有总览空状态引导，同时在无计划时为桌面侧栏、移动顶部计划区域和移动导航提供至少一个直接创建入口。
- 不改变计划、记录和备份的数据结构；校验发生在保存前，错误不会写入存储。
- 继续使用原生 `input[type=range]`，不引入新的可访问性依赖。
- 所有新增用户文案通过现有 i18n `t()` 入口提供中英文版本。
- 现有工作区中的未提交改动视为前置工作，不重置、不覆盖。

## 设计

### 1. 首次创建入口

`Layout` 的 `PlanSelector` 在无计划时显示按钮而不是只有文本。按钮调用 `onNavigate('settings')`，文案为“创建第一份计划”。该入口在桌面侧栏和移动顶部计划区域都可见；移动底部导航的设置入口继续保留。`Dashboard` 的现有空状态按钮和说明保留，形成第二条路径。

### 2. 统一表单校验与失败反馈

`Settings` 增加纯函数 `validatePlanDraft(form)`，返回稳定的错误键和首个错误区域。校验覆盖：

- 名称去空白后为空；
- 固定预算必须为正数，无限定投的每期目标不得为负数；
- 固定预算期数必须为正整数；
- 至少一个资产；
- 权重总和必须为 100%；
- ticker 去空白并转大写后不得重复。

保存按钮仍可根据有效性禁用，但点击或提交失败时必须更新 `validationErrors`。页面顶部设置 `role="alert"` 与 `aria-live="assertive"` 的错误摘要；每个错误在所属字段/资产区附近显示，字段设置 `aria-invalid` 与 `aria-describedby`。保存失败后用 ref 聚焦并滚动首个错误元素。校验成功后清除错误并保持现有保存流程。

### 3. Range 控件无障碍

以下控件各自拥有稳定的 `id`、显式 `label` 或 `aria-label`，并通过相邻 `output` 与 `aria-valuetext` 暴露当前值：保留现金比例、目标年化收益率、新资产权重、已有资产权重。每个已有资产的权重 label 包含 ticker，避免多个同名控件。保持原生 range 的键盘操作与现有 `:focus-visible` 样式。

### 4. 金融边界说明

在 FAQ 中增加统一的中英文条目，明确说明：工具不是投资建议；默认不计税费、手续费、滑点、分红和汇率影响；自动行情可能延迟或失败；计划和记录保存在浏览器本地；自动行情请求会把 ticker 发送给行情服务；清除浏览器数据或更换设备前应导出 JSON。设置保存区、行情区域和备份相关位置各放一条短说明，避免用户必须只依赖 FAQ 才能看到关键限制。

### 5. 日期、记录与行情来源状态

`Dashboard` 使用当前本地日期比较下一期计划日期。若下一期日期早于今天且计划未完成，显示明确的“已逾期”状态与操作入口；若计划尚无记录，显示“先进入本期操作录入第一期”的下一步。行情状态同时说明来源和时间：自动行情显示服务返回时间，旧记录显示最近执行记录日期，手动输入显示手动记录日期；请求失败时保留旧值并明确标记为旧数据/执行日价格，避免被理解为实时准确市值。

### 6. 结构化数据与 FAQ 语言

从 `index.html` 的 `SoftwareApplication` JSON-LD 删除没有真实依据的 `aggregateRating`，保留真实的名称、免费 offer、运行环境、描述、作者、网址和功能列表。FAQ 继续由 `FAQS_BY_LANGUAGE` 和 `createFaqStructuredData(language)` 生成；中英文 FAQ 文案、动态 `FAQPage` schema、页面 title/description、canonical 和 Open Graph URL 使用同一个语言状态，离开 FAQ 时恢复主页元数据。补充测试确保两种语言的 schema 内容与可见 FAQ 一致。

## 测试策略

- 增加无计划 Layout/导航入口的结构或静态组件测试。
- 为 `validatePlanDraft` 添加每类错误和通过场景测试，并测试保存失败时摘要、聚焦/滚动标记存在。
- 为四类 range 控件添加静态无障碍测试，检查 label、`output`、`aria-valuetext`、`aria-invalid` 和焦点样式。
- 为 Dashboard 添加无记录、逾期、自动/旧记录/手动行情来源状态测试。
- 更新 FAQ/SEO 测试，确认没有 aggregateRating，且中英文结构化数据与可见条目保持一致。
- 完成后运行 `npm test` 与 `npm run build`。

## 非目标

- 不实现真实交易、税费模型、滑点模型或保证行情实时性。
- 不改变存储键、备份格式或现有计算公式。

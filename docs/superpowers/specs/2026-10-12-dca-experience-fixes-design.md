# DCA Tracker 第四阶段产品体验修复规范（修订版）

状态：已按复审补充三项规则，连同实施计划待审阅；本次不开始产品实现。
修订日期：2026-10-26（Asia/Taipei）。本版替代 2026-10-12 初稿。

## 1. 目标、依据与约束

让首次用户直接创建计划；让保存失败可理解、可恢复；让滑杆可由键盘和辅助技术使用；让日期、估值、隐私和金融边界表述有事实依据。

### 已核对的现状

- `Settings.jsx` 和 `usePlan.js` 分别定义期数上限 10000、无限定投占位期数 9999、保留现金上限 0.3。多处使用 Math.min/Math.max、Number(value) || 0 修正输入；numericInput 的整数模式会截掉小数，不能直接用于保留待校验的原始草稿。
- `backupSchema.js` 的 BACKUP_LIMITS 规定最多 50 份计划、每计划 100 个资产、5000 条记录和 10000 期。ticker 规范化后为 1–20 字符，格式 `^[A-Z0-9][A-Z0-9.-]{0,19}$`；行情接口采用同样格式，单请求最多 20 个 ticker。
- `api/quotes.js` 的 asOf 是响应生成时间；服务可能返回缓存价格。当前上游 /price 没有提供可验证的交易所行情时间。
- 计划保存涉及计划列表、活动计划 ID、兼容旧计划键和重建记录；现有回调没有返回完整持久化结果，setState 不能代表保存成功。
- FAQ 有运行时内容、faq.html 静态正文和静态 JSON-LD 三份输出，两种语言共用 /faq 路由。

### 实现方向与边界

- 沿用已确认的局部 UI 修复和共享校验/展示逻辑方案，不增加交易系统或多语言路由。
- 将共用数值和 ticker 规则提取到公共约束模块（建议 src/utils/planConstraints.js），供草稿、保存、备份和行情边界复用；保留 BACKUP_LIMITS 兼容导出，不各自维护不同数值。具体文件拆分留给实施计划。
- 本地旧数据可读取并进入数据修复状态；导入备份必须通过日期/身份完整性检查，失败不覆盖现有数据。显式保存必须通过草稿校验，不借兼容规则静默改写数据。保留存储键、备份版本与字段兼容性，不增加强制备份字段；允许内存中的逐标的行情展示元数据和内部保存结果接口。
- 新增文案提供中英文，保留原生 range。测试可按实际需要增加 DOM/浏览器测试工具，但本轮不安装依赖。现有未提交改动视为前置工作，不重置或覆盖。

## 2. 首次创建计划入口

### 实现规则

- 无计划时桌面侧栏计划区显示“创建第一份计划”；移动顶部或底部至少一处显示同文案直接入口。窄屏 CSS 不得隐藏所有创建入口。
- 从任意页面一次操作进入设置的新计划草稿；保留合理默认预算/周期，不自动保存。已有计划选择器仅用于切换，创建和保存位于设置页。
- 保留总览无计划及无记录的引导。入口有可访问名称、可见焦点和至少 44×44 CSS px 触控区域，文字可换行。

### 可观察验收

- 清空计划，从总览、历史、FAQ 分别点击入口，直接看到设置页名称和资产字段，存储没有自动新增计划。
- 320/375 CSS px 窄屏及桌面上入口可见、可点，无工具栏遮挡；Tab 可到达，Enter/Space 可激活。
- 有计划时实际切换所展示的计划；现有总览空状态按钮仍能导航。

## 3. 保存交互、表单校验与持久化结果

### 3.1 保存交互和错误反馈

- 分开维护 isFormValid、hasSubmitted、isSaving、saveError。无效草稿的保存按钮仍可操作；仅保存进行中禁用，显示“保存中”及 aria-busy，防止重复提交。
- 一次保存使用提交时的草稿快照；isSaving 期间暂时锁定本草稿字段及撤销/创建/删除等重置操作，完成或失败后恢复，避免成功保存的快照与屏幕草稿不一致。显式离开设置或切换计划时不得被晚到的保存回调拉回总览或重置新草稿；用提交上下文标识隔离结果。该锁定是本规范选择的实现规则。
- 点击保存或提交表单先完整校验；失败不调用存储、不导航。保存区显示错误摘要，每条可定位对应字段；相关区域附近同时显示具体原因。
- 错误渲染完成后聚焦并滚动首错，按表单 DOM/视觉顺序：名称→当前预算→期数→参数→资产各行→总权重。同一行 ticker 先于权重和持仓字段。
- 聚焦实际输入控件；无资产或总权重错误聚焦可程序聚焦的资产错误区域（tabIndex=-1），附近保留添加/调权重操作。行标识不只使用 ticker，以免重复时误改/误删多行；ticker 编辑/删除遵守 §3.4，已有重复或损坏关联不得通过猜测身份来修正。
- 首次提交后，字段、预算模式和资产列表变更都重新校验，更新所有已显示错误及摘要，移除已修复错误并加入新错误；编辑时不抢焦点/滚动。重试提交才再次定位首错。首次提交前不将整页未填写字段全标红，添加资产可有独立的行校验。
- 字段通过 aria-invalid、aria-describedby 关联错误。使用一个预先挂载的 aria-live=polite、aria-atomic=true 摘要状态区，播报提交失败数量及首错、错误数量变化、保存中和存储失败；避免多个 live region 重复播报。错误不只靠颜色区分。

### 3.2 validatePlanDraft 契约与数值规则

- 纯函数 validatePlanDraft(form, context) 返回 `{ isValid, errors, firstErrorField }`；context 为 `{ existingPlanIds, editingPlanId, planRecordCount, assetIntegrity }` 的只读快照，明确提供计划数量/编辑身份/当前计划记录数及 §3.4 的关联检查结果，不从 localStorage 隐式读取。errors 为有序 `{ field, code, params }` 列表，支持 assets[index].ticker 等路径；插入/删除行后按当前行标识重算定位。函数不修改输入、不写存储、不导航；错误码经 i18n 转文案。持久化前协调层以当前真实上下文再校验一次，避免过期快照绕过上限。
- 先识别空串/全空白/null/undefined，再严格解析完整十进制文本并检查 Number.isFinite。不得用 parseFloat 接受 12abc，不得把空白、NaN 或 Infinity 用 || 0 当作合法值。允许前后空白；科学计数法不作为设置输入的合法格式。
- 原始错误输入保留到用户修正；onChange、onBlur、normalizeFormPlan、模式切换、序列化、保存 hook 均不得把 10001 截成 10000、1.5 期截成 1、负数去掉符号或非法文本转成 0。合法金额/价格沿用已有显示精度；格式化不承担纠正越界输入的职责。

| 字段 | 明确规则 | 就地错误位置 |
| --- | --- | --- |
| 名称 | 字符串 trim 后非空，保存 trim 后的值 | 名称下方 |
| 固定总预算 | 必填、有限且 >0 | 总预算下方 |
| 固定期数 | 必填、安全正整数，1–10000 含端点；不得小于当前计划已有记录数 | 总期数下方 |
| currentPeriod | 两种模式均为 0–10000 的安全整数；用户不能编辑的损坏值显示结构错误，不自动截断 | 结构检查区 |
| 无限每期目标 | 必填、有限且 ≥0；空白错误，显式 0/0.00 合法。0 附近说明“本期目标投入为 0，可自行决定实际投入” | 每期目标下方 |
| 无限内部期数 | 非用户终点；新草稿沿用 9999，占位期数与 currentPeriod 均须在 0–10000 的安全整数范围，不截断损坏值 | 结构检查区 |
| 保留现金 | 固定模式有限值且 0–0.3；无限模式按业务规则为 0 | 保留现金附近 |
| VA 年化参数 | 有限且 >-1、≤10，沿用已有数据计算范围；滑杆仍选 0–0.5。合法旧值超出滑杆范围时可见并可数值编辑，不能自动重置。DCA 不因隐藏 VA 参数阻塞保存 | 目标年化附近 |
| 资产集合/计划数量 | 每计划 1–100 个资产；新增计划遵守 50 份上限，编辑不误算成新增 | 资产区/保存区 |
| ticker | trim+大写后匹配共享格式，同一计划不得重复；标识全部冲突行 | 对应 ticker 附近 |
| 单项权重 | 必填、有限且在 [0,1]，允许单项为 0，不允许正负抵消 | 对应权重附近 |
| 总权重 | 仅单项全合法时求和，共享 WEIGHT_SUM_TOLERANCE=1e-6，Math.abs(sum-1)<=1e-6 通过；不先舍入整数百分数 | 总权重区 |
| 初始股数/均价 | 可空（明确表示未提供，沿用现有保存的 0）；非空必须有限且 ≥0，不得把错误文本当缺省值 | 对应持仓字段下方 |

- 单项无效显示单项原因及“总权重无法校验”；总和不合格显示足以解释差额的精度，不显示看似通过的整数 100%。资产添加和最终保存均检查格式、重复、数量。
- budgetMode、strategy、market、frequency 只接受当前选项集合（fixed/open-ended、VA/DCA、US/CN、monthly/biweekly）；非法旧值显示对应参数错误，不默认为另一个有效选项。
- 模式切换只校验当前模式可编辑预算字段，隐藏旧值不阻塞；切回时保留原草稿以供修正。自动均分、关闭添加区等不得悄悄消除错误。

### 3.3 持久化结果契约

- onSavePlan(nextPlan) 明确返回或 resolve `{ ok:true }` / `{ ok:false,error }`；异常视为失败。undefined、回调已调用或 setState 已执行均不代表成功。
- App/协调层收集本次所有必需写入结果：计划列表、活动 ID、兼容旧计划及重建记录。hook 返回真实结果，写入副作用不得放在可能重复执行的 React state updater 内。
- 全局记录容量 5000 由持久化协调层在写入前检查，不由只看单计划草稿的 validatePlanDraft 猜测。保存计划重建后记录数等于 5000 可保存，超过则报结构/容量错误且不得截掉记录。新增操作要求全局现有记录数小于 5000，达到上限阻止新增并在操作页与 Dashboard 显示导出/整理记录指引；已有计划编辑及记录编辑/删除不因“已恰好到限”被阻止。
- 先准备新数据与旧快照；必需写入全部成功才发布新内存状态、更新数据变更标记并返回成功。Settings 是本次提交导航的唯一负责者，成功后才进入总览。
- 任一必需写入失败即返回错误，不再写非必要键，尽力用旧快照补偿已完成写入；不发布成功状态。localStorage 多键不是事务，不承诺浏览器故障下绝对原子性。若补偿也失败，明确提示“部分数据可能已写入，请重试或导出备份”，不得假报恢复。
- 补偿失败时导出备份使用最后确认的内存计划/记录，并明确这份 JSON 不含尚未保存的草稿；不得提示已备份草稿。保留草稿后可继续重试，恢复错误期间不以自动重建 effect 覆盖该草稿或偷偷导航。
- 失败留在设置，完整保留字段、资产和草稿 ID，不重置、不导航。保存区显示并播报错误，聚焦该错误区；退出 isSaving，允许修改后重试。新计划重试复用草稿 ID，不能新增重复计划。字段修正不会清除尚未解决的存储错误，重试成功才清除。

### 可观察验收

- 空草稿的按钮可点；一次提交同时显示名称和资产等错误，document.activeElement 是名称输入且实际可见。修复名称后摘要/就地错误同步消失，编辑焦点不跳走。
- 覆盖预算空/0/负数/Infinity/非法文本，期数 0/1.5/10000/10001，权重负数/>1/NaN，无资产，spy 与空白包围的 SPY 重复，非法/超长 ticker；无效时存储回调为 0 次。
- 无限空白报错，显式 0 可通过；0.1+0.2+0.7 权重通过，0.999998 不通过，容差内外与单项边界都有用例。
- pending 保存时按钮禁用；模拟第一/中间写入失败、异常及补偿失败，确认留页、保稿、播报、无成功导航。重试成功只有一份计划，进入总览，刷新可读取正确数据。

### 3.4 ticker 身份、删除限制与数据修复状态

- 对当前已保存计划，按规范化 ticker 检查全部历史 record.assets 和全部 splitEvents（包括未来事件）。无历史记录且无拆合股关联的资产可编辑 ticker/删除；有任一关联即阻止这两种操作，附近解释“此资产已有关联历史记录或拆合股事件，本阶段不能更改代码或删除，以免历史失去对应资产”。仍可修改合法权重等不改变身份的字段。
- UI 禁止和保存前检查同时生效；在保存协调层比较已保存身份与候选草稿，阻止绕过 UI 的删除/改名。不将历史 ticker、事件 ticker 或记录 planId 级联替换，不因删除资产悄悄删除事件。新草稿里的临时行 ID 仅用于焦点/key/定位，不成为新持久化资产 ID，不据此猜测历史属于哪一行。
- 未保存的新资产可改名/删除；有草稿拆合股关联时先明确移除关联草稿事件才可操作，不隐式删除事件。已经存在关联的资产本阶段不提供借移除事件后同次保存改名的捷径；以已保存快照检查保护。
- 加载时就有重复 ticker、记录引用不存在的计划/资产、事件 ticker 无对应资产、重复/损坏关联等，进入单独“数据需要修复”状态，列出计划、ticker/记录/事件定位和原因。禁止普通保存、该计划新增操作、自动重建及依赖不明身份的估值，避免 Map 合并或丢弃原数据；无关健康计划仍可用。保留原始数据、只读查看和原始恢复 JSON 导出，引导从校验通过的备份恢复。本阶段不实现自动合并、重命名或历史身份迁移。
- 新草稿用户造成的重复 ticker 是普通表单错误，可通过编辑无关联的行修正；与“加载时已有重复”的修复状态分开。导入遇到身份损坏应明确拒绝且不覆盖现有数据；原始恢复 JSON 不承诺能直接正常导入。

验收：无关联资产可改名/删除后保存；有关联历史、已生效或未来事件的资产 UI 和直接调用保存均被阻止，历史/事件快照逐项不变。加载重复/孤立关联显示修复原因，不自动重建。健康计划保存后，所有 record.planId、record.assets.ticker、splitEvents.ticker 都有唯一有效归属，导出 JSON 可重新导入。

## 4. Range 可访问性

### 实现规则

- 保留现金、目标年化、新资产权重和各已有资产权重均用原生 range，具备 label[for] 或 aria-label/aria-labelledby。新资产叫“新资产权重”，已有行名称包含 ticker；id 唯一且不只依赖 ticker。
- 关联 output 展示百分数，aria-valuetext 同步读出如“20%”；原生 min/max/step/value 一致。精确权重差额不能被整数百分数掩盖。
- 默认支持 Tab、方向键、Home/End，每步 1 个百分点；保留现金 0–30%、年化滑杆 0–50%、新资产 5–100%、已有资产 0–100%。不自定义阻断原生键盘行为，端点不越界。
- 两种主题的 focus-visible 清晰、未裁剪、未被固定导航遮住；修改后可访问名称、值和错误关系仍正确。

### 可观察验收

- 挂载 DOM，按 role/name 找到四类 slider，打开添加区覆盖新资产滑杆；逐项断言可访问名称及实际值。
- 实际发送 Tab、ArrowRight/Left、Home/End，断言 input/output/aria-valuetext 及草稿同步，再保存验证采用值。
- 真实浏览器检查日夜焦点可见，基础可访问性扫描与名称/描述断言配合使用，不以扫描通过替代键盘检查。

## 5. 行情来源、时间与组合估值

### 5.1 逐标的内存元数据

- Dashboard/本期操作对每个 ticker 维护实际使用价格和来源，可在内存增加 `{ price, source, lastSuccessfulFetchAt, recordDate, manualEnteredAt, requestStatus }`；不要求持久化或改变备份。来源区分 auto、record-auto、record-manual、record-unknown、manual、missing。请求状态和价格来源分开，失败不把旧自动价改标手动。
- lastSuccessfulFetchAt 是客户端成功接收并验证该 ticker 有限正价格的时间，文案“最后成功获取时间”。接口 asOf 只可称“服务响应生成时间”；不能用批响应时间更新失败 ticker 的成功时间。缓存响应也不证明价格新鲜。
- 没有交易所时间时显示“行情时间未提供，可能延迟”；不得写“实时”“准确当前价”或仅以获取成功标 fresh。显示日期、时分和明确本地时区，按当前语言格式化，内部用有效 ISO 时间；缺失为“时间未知”。
- 历史回退逐 ticker 选当前计划内执行日期最新且含有限正原始价格的记录；同日依较高 periodIndex、再按稳定 ID 排序选定。更近记录没该 ticker 或价格无效不能覆盖旧有效值。无效日期不参与可靠估值；仅剩无效日期的价格可只读列为“记录日期未知”，不得加入组合估值。换算规则见 §5.3。
- record-auto/manual 来自实际采用记录的 priceSource，缺失则 record-unknown；展示该记录执行日期，不以组合最近记录日期代替，不从执行日推造获取时间。
- 当前手动编辑设置 manual 及内存 manualEnteredAt（输入时间），与操作执行日期分开。旧手动记录只显示“手动记录价格+记录日期”，不能伪造本次输入时间。清空/非法价格为 missing；初始持仓成本不作市价回退。
- 价格优先级：本次手动覆盖（操作页）→该 ticker 本会话最近成功自动价→该 ticker 历史参考→missing。手动编辑后晚到响应不得覆盖；只有用户明确再获取且成功才替换。切换计划/标的隔离元数据，取消或忽略过期响应。
- 手动覆盖由“用户已编辑”标志决定，不由价格是否有效决定：主动清空/输入非法文本后仍为手动覆盖，所用价格是 missing，不回退自动价或记录价；相关建议/确认不使用旧价。用户修正为正价格，或明确点击自动获取并成功，才能解除缺价。再次获取失败仍保留空/非法输入和缺价状态。尚未进行手动编辑时，才按自动→记录→missing 回退。

### 5.2 刷新状态矩阵

成功数量按本轮全部唯一 ticker 统计；HTTP 200 遗漏 ticker、无效价格、某批失败均算对应失败。超过接口每请求 20 个时分批合并一轮结果，不把可保存的第 21 个资产排除。

| 状态 | 价格及时间规则 | 可见反馈 |
| --- | --- | --- |
| 首次获取尚无值 | 显示 --，不以 0 填未知 | 正在获取；各缺值项暂无价格 |
| 刷新中有旧值 | 保持价格、来源和成功时间，仅改变请求状态 | 刷新中，暂用上次/记录价格 |
| 全部成功 | 逐项更新价格、auto、成功获取时间 | 本次获取 N/N；行情时间未提供，可能延迟 |
| 部分成功 | 仅成功项更新时间；失败项保留旧自动价，否则各自历史价，否则 missing | 本次获取 K/N，部分失败；逐项未更新及来源/时间 |
| 全部失败但有旧值 | 不改成功时间，旧自动优先于历史参考 | 获取失败，使用上次获取/历史参考价格；标出缺价 |
| 全部失败且无值 | --，不伪造零市值 | 获取失败，暂无可用价格；重试/手动录入入口 |

- 总市值附近始终“参考估值，非实时”，可查看逐标的来源/时间。多种来源或不同轮次自动结果混用时，加“使用混合来源或不同时间的价格”。
- 任一正持仓资产缺价：完整总市值/盈亏显示 -- 和“估值不完整：X 个持仓资产缺少价格”。可另列“已知部分估值”，不能冒充完整总值。零持仓可为 0，不要求价格。
- 全局“已更新”不能覆盖日期未知/部分失败提示；不设无依据的实时阈值，最后获取时间也不消除行情延迟说明。

### 可观察验收

- A 本轮成功、B 失败但有昨日自动价、C 只有上周手动记录价：A 时间更新、B 时间不变、C 为自己记录日期，总值附近显示混合来源与非实时。
- HTTP 200 只返回部分有效 ticker 必须显示部分成功；刷新不闪零；全失败保留旧值；首次失败显示缺价与不完整估值。
- 更近记录仅含 A 不改变 B 回退日期；旧备份缺 priceSource 标来源未知；无效日期不伪造。
- 操作页失败保留来源，手动输入后晚到响应不覆盖，切换计划无污染；21 个 ticker 分批并正确汇总。旧备份可导入，导出无强制新增时间字段。
- 已有自动价时手动清空，界面显示缺价、操作确认不可用，不能重新显示旧自动值；自动重试失败仍缺价，成功才采用新值及其获取时间。

### 5.3 历史回退的拆股/合股口径

- 为一次估值确定明确的本地估值日 asOfDate，持仓股数与回退价格使用同一个估值日和同一份事件快照。显式把 asOfDate 传给现有 getSplitFactor/getSplitFactorBetween，再把所得因子传给 adjustAssetForSplit/adjustHoldingForSplit，不能依赖工具的默认 UTC 今天或无效日期回退到 9999-12-31。
- 原始 record.assets.price、actualShares 及执行日是历史原始口径；adjustedPrice、adjustedShares、splitFactor 是派生缓存。以原始 price 为起点，用现有因子计算 `F=∏(newShares/oldShares)`，事件范围严格为 `执行日 < 生效日 <= 估值日`，同日记录按现有约定已是生效后口径；当前参考价=原价/F。不对 adjustedPrice 再除 F，不把缓存写回原价。缺 adjustedPrice 的旧备份只要原价/日期/事件可靠，仍按此规则计算。
- 多事件累乘（包括先拆后合），未来事件排除；重复渲染、刷新或重建必须幂等。持仓已在估值日口径时不再次调整；重建若需更新持仓必须从原始初始持仓和原始记录派生，禁止把当前持仓作为原始再乘一次。保留原始交易金额，金额不因拆合股重写。
- 自动价视为本次获取的市场参考价，不用历史拆合股因子调整；若自动/手动旧值跨过新增已生效事件而无可确定的口径基准，标记不可可靠估值，须重新获取/确认价格。只凭获取时间不推断行情实际对应的交易时刻。
- 日期无效、执行日在估值日之后、原始价格缺失仅有 adjustedPrice、事件日期/比例损坏、重复事件或原始/缓存口径矛盾且不能解释时：保留可查看原数据，标“不可可靠估值：日期或拆合股口径不明确”，该正持仓资产按缺价规则阻止完整总值/盈亏。不得当作因子 1 或无事件成功估值；原始事件在 normalizeSplitEvents 丢弃坏项之前先检查完整性。
- UI 保留实际采用记录的执行日期，展示“历史参考价已按截至 {估值日} 生效的拆/合股换算（累计因子 {F}）”；无事件则不虚构调整。估值日变化或事件变更重新计算来源说明。

验收固定原价 120：2:1 拆股后价 60，1:4 合股后价 480，连续 2:1 与 1:4 后因子 0.5、价 240；估值日之后的事件不参与。使用与原始股数对应的当前股数，换算前后价值相同（受既有显示精度约束）；有/无 adjustedPrice 都得到相同结果，重复执行不重复调整。覆盖未来事件、生效当天、无效日期、缺原始口径和损坏事件；不能可靠计算时显示原因及不完整总值。

## 6. 日期与下一步操作

### 实现规则

- 今天由浏览器本地年/月/日组成，不使用 toISOString().slice(0,10)；日期严格验证闰日/月末存在性，按日历日比较，不用毫秒除以 24 小时推算逾期天数。
- 记录 date 表示执行日，既有 YYYY-MM-DD 或 ISO 序列化保留已保存的日期部分，不再次时区移动。createdAt 为时间戳时转本地日历日；纯日期按日期处理。
- 完成期数用当前计划记录数。最近一期取最高 periodIndex 的记录，不是最晚日历日期；下一期月度加一个日历月（月末收敛），双周加 14 个日历日。无记录时第一期取创建日，不多加一周期。
- 有记录但最高期的日期无效，显示“日期未知，请检查最近记录”，不回退创建日/其他记录。无记录且创建日无效也未知。
- 固定计划记录数≥总期数，优先显示“计划已完成”；不显示下一期编号、预计日期、逾期或执行入口，改为“调整计划/创建新计划”。
- 完成比较的前提是 totalPeriods 为合法范围内正整数；频率、总期数、记录序号等结构无效时显示“计划状态未知，请到设置检查”，不把 NaN/0 当作完成或默认月度。合法固定计划已完成时，即使最近执行日期缺失也不再计算下一期；未知状态保留检查/修正入口。
- 无限计划不以占位 totalPeriods 判完成；正常判断到期。达到现有计算/记录容量上限时显示明确限制及设置/导出指引，不生成非法期号或承诺仍可执行。
- 未完成的互斥状态：日期<今天“已逾期”，=今天“今日到期”，>今天“待执行”，非法“日期未知”。当天不算逾期；无记录同时显示“录入第一期价格与实际买入股数”。逾期不隐藏入口，未知日期可进入操作人工核对。
- 连续记录只描述历史连续性，删除“当前没有漏投”等推论。逾期写“下一期已逾期，请核对是否尚未记录”；历史暂停不抵消当前逾期。
- 挂载计算，按本地下一个午夜设置更新并重新安排定时；window focus、visibilitychange 回到 visible、pageshow 时重算；卸载清理，避免后台跨日后显示旧状态。

### 可观察验收

- 本地今天 2026-10-26，下一期 10-25/26/27 分别逾期/今日到期/待执行；固定完成无下一期入口，无限同规则且不以 9999 占位值完成。
- 无记录创建日为今天，显示第一期及引导；最新期日期非法闰日/空值显示未知，不回退创建日。
- 覆盖 1 月 31 日加月、闰年、双周跨月跨年、未来执行日；未来日期按记录日加周期，不生成负逾期。
- Asia/Taipei 和 America/Los_Angeles 浏览器上下文验证 UTC 换日附近本地今天/创建日；验证午夜自动更新和后台跨日后聚焦更新，记录业务日期不漂移。
- 逾期、暂停、连续多期组合不出现相互矛盾文案。

### 6.1 执行日兼容贯穿创建、保存、导入与导出

- 使用统一 parseExecutionDate(value) 返回合法 YYYY-MM-DD 或 null；接受纯日期和明确旧格式 `YYYY-MM-DDTHH:mm:ss[.SSS](Z|±HH:mm)`（毫秒省略或恰好三位）。允许输入字符串前后空白，不接受无时区时间戳、任意尾缀、地方日期格式、数字 epoch。小时 00–23、分/秒 00–59、偏移最大 ±14:00（14 时只允许 00 分），不接受 24:00 或闰秒。年份 0001–9999，严格校验真实日历，不能仅以 Date.parse 未返回 NaN 判断。
- 对旧 ISO 提取并验证文本的业务日期部分，不把它转换到本地日期；例如 2026-10-26T00:00:00.000Z 和 2026-10-26T23:30:00-07:00 的执行日都为 2026-10-26。createdAt 是真实时刻，仍按 §6 转本地创建日，不与执行日解析混用。事件 effectiveDate 采用同一日历校验基础，但仍要求纯日期。
- 新建和编辑记录都保存 canonical YYYY-MM-DD；操作页默认执行日为本地今天。App 保存/重建、History 展示/CSV、备份导入校验及正常 JSON 导出都调用同一解析规则；无版本旧备份也必须走规范化结果，不能校验后再返回未经规范化原记录。
- 正常导出将有效旧 ISO 规范为业务日；纯导出/导入解析不重算金额或改写原始股数、价格、actualAmount、累计金额。导入后的估值重建从原始字段派生，不信任旧 adjusted 缓存。导入非法日期应明确错误路径并拒绝全次导入，不改现有数据；正常导出遇到损坏日期/身份时说明无法生成可恢复备份，提供单独原始恢复导出，不伪造 1970-01-01、今天或下一个有效日。原始恢复 JSON 保留原值且不承诺通过正常导入。
- 完整回归必须操作“创建记录→导出 JSON 下载→清空测试存储→导入同一文件→重新展示和导出”，既覆盖纯日期，也覆盖明确支持的旧 ISO。台北与洛杉矶各执行，并把一地导出文件在另一地导入；执行日、原始交易股数/价格和实际/累计金额始终不变。在相同 asOfDate、相同事件快照下，当前持仓及派生股数/价格/拆合股结果也必须相同。若两地本地估值日不同且跨事件生效日，允许按 §5.3 重新派生，必须显示新估值日和调整说明；这不属于业务日期漂移，不能借此改写原始交易。拒绝 2025-02-29、2026-02-30（含 ISO 形式），接受 2024-02-29；DST 附近同样验证。
